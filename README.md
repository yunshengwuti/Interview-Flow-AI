# Interview Flow AI

面向招聘 HR 的面试邀约与排期协调 Agent 产品原型。

本项目聚焦校招等批量邀约场景：由 HR 设置面试计划，Agent 承担邀请执行、反馈识别和明确结果处理，将需要人工判断的情况转交 HR。

## 项目背景

HR 在参与面试的同时，还需要安排面试、跟进候选人回复，并处理改期和放弃等变化。

Interview Flow AI 希望减少逐人发送邀请、反复查看邮件及核对排期的工作，让 HR 集中处理异常和作出决策。

## 核心功能

| 功能 | 说明 |
| --- | --- |
| 执行面试邀请 | 根据计划分配时段，在指定时间发送邀请 |
| 监听候选人反馈 | 接收邮件按钮操作和文本回复，关联候选人与批次 |
| 反馈处理与异常转交 | 自动处理明确的参加或放弃结果，将改期、恢复参加及意图不明确的反馈交给 HR |
| 空位释放与补位提醒 | 维护空位，经 HR 批准后，按入池时间先后顺序（FIFO）执行补位 |
| 日志记录 | 分别记录 Agent 执行与 HR 操作，保留时间及处理结果 |

## 核心流程

HR 创建面试计划  
→ Agent 执行邀请  
→ 候选人通过按钮或邮件回复  
→ 明确结果自动处理，异常转交 HR  
→ 更新状态与排期  
→ 满足条件时提醒补位  
→ HR 批准后，Agent 按 FIFO 发送补位邀请

## 第一版边界

- 不承担简历初筛和人岗评价，以已有候选人池为前提。
- 不自主开展多轮沟通或协商改期。
- 不在空位释放后立即补位，补位邀请须经 HR 批准。
- 明确区分按钮反馈与文本反馈：前者按规则处理，后者需要识别意图。

## 原型说明

当前版本用于展示产品流程、交互和业务规则：

- 候选人及反馈为预设案例。
- 尚未接入真实邮件 API、招聘系统或大模型服务。
- 页面中的发送和反馈处理不代表真实邮件已发出或被接收。
- 交互数据保存在当前页面内存中，刷新后恢复初始状态。
- 原型展示不等同于生产环境能力或实际验证结果。

## 验证思路

采用交叉对照的受控场景测试，比较人工处理与 Agent 辅助处理，重点观察：

1. 异常发现时间与处理速度
2. 反馈处理准确度及异常转交情况
3. 目标用户是否愿意继续使用

内部测试用于发现问题和判断提效潜力，HR 的实际使用意愿仍需目标用户参与验证。
